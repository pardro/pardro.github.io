고객상담 AI Agent

현업 니즈 발굴부터 STT 재구축, 실시간 상담 지원과 준실시간 품질 평가까지 연결한 고객상담 AX 프로젝트.

담당
고객상담 분과 PL · 활용 사례 발굴 · STT 학습·서빙 및 Agent 연계 설계
기술 / 방법
AI Agent · STT · KMS · Python

배경과 과제

「AX를 위한 AI Agent 구축 사업」의 여러 분과 중 고객상담 영역을 담당했습니다. 고객과 밀접하게 접하는 현업 부서가 실제 업무에 사용할 Agent를 구축하는 프로젝트로, 고객센터·분쟁민원조정부·디지털영업부 등의 니즈를 듣고 분석해 활용 사례를 발굴했습니다.

고객상담 담당 분과 PL로 사업 운영을 수행했으며, 고객센터에서는 STT 고도화와 Agent 연계를 통해 상담 중 지원부터 상담 종료 후 요약·품질 평가까지 이어지는 흐름을 다뤘습니다.

현업 인터뷰와 활용 사례 발굴

부서별 업무와 니즈 분석

고객센터, 분쟁민원조정부, 디지털영업부 등 대고객 부서의 현업 담당자를 인터뷰하고 업무별 니즈를 분석했습니다. 현업에서 실제로 사용할 수 있는 Agent의 활용 사례를 구체화하는 과정이었습니다.

기존 STT의 사용 저조 원인 파악

활용 사례를 발굴하는 인터뷰 과정에서 기존 STT의 인식 성능이 다소 낮고 연계 서비스가 없어, 많은 직원이 사용하지 않고 있다는 점을 파악했습니다. STT 자체의 개선과 함께 인식 결과를 실제 상담 업무에 활용하는 연계 흐름을 다뤘습니다.

STT 재구축과 상담 단계별 Agent 연계

학습 데이터 수집부터 학습·서빙까지

STT를 재구축하기 위해 학습 데이터를 수집하고 모델을 학습·서빙하는 전 과정의 방향을 결정했습니다. 상담 과정에서 생성되는 STT 상담 내역을 Agent로 전달해 후속 업무에 활용하는 흐름으로 연결했습니다.

상담 중 실시간 지원과 종료 후 준실시간 처리
시점데이터 활용지원 기능
상담 진행 중 · 실시간STT 상담 내역을 Agent로 전달키워드·질의어 추천, 관련 지식 검색, 답변 추천
상담 종료 후 · 준실시간상담 내용을 후속 처리에 활용상담 요약, 상담 품질 평가

상담 품질 평가의 준실시간 전환

다음 날 확인하는 배치 요건 재검토

기존 요건은 플랫폼에 등록한 특정 상담을 야간 배치로 평가하고 다음 날 결과를 확인하는 방식이었습니다. 개발 과정에서 현업의 실시간성 요구를 추가로 확인하고, 상담 품질 평가를 준실시간으로 처리하도록 요건을 변경했습니다.

서비스 DB 저장 전 Agent 전달 경로 제안

서비스 파이프라인을 검토한 뒤 데이터를 서비스 DB로 보내기 전에 Agent로 바로 전달하는 방법을 생각했습니다. 데이터의 전달 시점을 앞당기는 방향으로 기존 배치 요건을 검토했습니다.

인프라·데이터·Agent·프런트 담당자 간 협의

변경 가능성을 검토하기 위해 인프라, 데이터, Agent, 프런트 등 여러 담당자를 찾아 논의했습니다. 현업의 니즈를 서비스 흐름의 변경으로 연결하고 관계자들과 협의해 요건을 조정했습니다.

Rubric 기반 상담 품질 평가

필수 안내 누락, 상담 품질, 절차, 태도 등 다양한 항목을 Rubric으로 정리해 상담을 평가합니다. 평가 항목을 명시적인 기준으로 구성해 상담 품질 평가 Agent에 활용했습니다.

전체 사업 범위와 고객상담 영역

전체 사업은 고객상담·기업금융·자산관리·내부통제·업무 자동화를 AI Agent로 연결하는 범위입니다. RFP는 서비스, Agent 플랫폼, AI 서비스 허브, 공용 솔루션, MCP, 레거시 연동, 데이터 관리의 7개 영역으로 구성됩니다.

고객상담 영역은 상담 지원과 품질 평가 등의 업무를 다루며, 공통 기반 중 STT로 수집한 상담 데이터, KMS의 업무 지식, 학습·서빙 Agent를 연결합니다. 고객상담 담당 분과의 PL로서 사업이 원활하게 진행될 수 있도록 사업 운영을 담당했습니다. 기술 범위에서는 STT 학습·서빙 파이프라인 설계를 수행했습니다.

구현 구조

상담 업무와 정보 활용 흐름 정리

고객센터 직원을 사용자로 설정하고 상담 과정에서 필요한 정보 탐색과 지원 업무를 정리했습니다. 고객 상담 데이터와 업무 지식이 활용되는 지점을 중심으로 서비스 요구사항을 구체화했습니다.

STT와 KMS 기반 구성

음성 상담 데이터를 활용하기 위한 STT 고도화와 새로운 KMS 구축을 진행했습니다. 상담 기록과 지식 검색을 상담 보조 업무에 연결할 수 있도록 데이터 수집·활용 흐름을 설계했습니다.

학습·서빙 Agent 파이프라인

고객센터에서 사용할 STT 학습·서빙 관련 Agent 파이프라인을 설계했습니다. 개별 모델의 개발뿐 아니라 상담 업무에서 데이터와 모델이 이어지는 전체 흐름을 검토했습니다.

담당 업무

고객상담 담당 분과 PL · 사업 운영

고객상담 분과의 사업 운영을 맡고 여러 대고객 부서의 니즈를 분석해 Agent 활용 사례를 발굴했습니다. 현업과 개발 관계자 사이에서 요구사항을 구체화하고 변경 요건을 협의했습니다.

STT 재구축과 학습·서빙 방향 결정

학습 데이터 수집부터 모델 학습·서빙까지 STT 재구축의 전 과정을 결정하고, STT 상담 내역을 실시간 상담 지원과 종료 후 처리에 연결하는 Agent 파이프라인을 설계했습니다.

AI 기능·한계에 대한 현업 소통

AI를 많이 접하지 않은 현업 직원에게 기능과 한계를 설명하는 것이 사업 진행 과정의 가장 큰 어려움이었습니다. 현업의 기대와 실제 구현 방향을 조율하는 소통을 수행했습니다.

결과와 기여

현업 인터뷰에서 파악한 STT 사용 저조 문제와 업무 니즈를 바탕으로, 음성 인식과 Agent의 실제 활용 흐름을 함께 다뤘습니다. 고객상담 담당 분과 PL로 활용 사례 발굴과 사업 운영을 수행하고, STT 재구축의 학습·서빙 방향 및 상담 단계별 Agent 연계를 설계했습니다. 상담 품질 평가에서는 서비스 DB 저장 전 전달 경로를 제안하고 여러 담당자와 협의해 다음 날 배치 요건을 준실시간 요건으로 변경했습니다.
